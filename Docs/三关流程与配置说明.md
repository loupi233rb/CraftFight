## 改哪些字段

- `spawnIntervalSeconds`：怪物生成间隔。第一只立即出现；设为 `0` 时同一帧生成本关全部怪物。
- `rounds`：按顺序保存三关配置，固定三条记录。
- `preparationSeconds`：本关合成倒计时，必须大于零。
- `combatSeconds`：本关战斗倒计时，必须大于零。
- `monsters`：`id` 与场景 MonsterSpawner 的预制体绑定对应；当前支持 `zombie`、`skeleton`，`count` 为非负整数。本关总数必须大于零。
- `resources.oak_plank`：木板。Hierarchy 中的生成器对象叫 `plank`，实际数据库物品名为 `oak_plank`。
- `resources.iron_ingot`：铁锭。
- `resources.flint`：燧石。

资源计数均为非负整数，表示进入本关合成阶段时的**新增领取额度**。生成器沿用原来的逐个出料方式，拿走当前物品后才继续出料，并非一次把全部资源堆在地上。生成器显示的数字是尚未生成的额度；场上已经生成但没拿走的一件也属于本关额度。

下一关开始准备时，清理上一关这些生成器生成且未拾取的资源，再设置新额度。玩家已经放进背包或拿在手里的物品保留。战斗阶段不继续出料；第三关完成后不再发新额度。

## 运行

打开 `Assets/Scenes/MainScene.unity` 后进入 Play Mode。人物进入空中等待点，移动和重力暂停；按 Enter、空格、任意一侧 VR 手柄扳机，或点击桌面上的 START GAME 按钮开始。

开始后：合成区 → 准备倒计时 → 战斗区 → 刷怪和战斗倒计时。战斗超时，或本关所有计划怪物已经生成且全部死亡，就返回合成区进入下一关。第三关结束后返回合成区，显示完成，不会启动第四关。

切换回合不恢复生命值。角色、金币、升级、背包与手持物品均保留。玩家死亡则失败，停止刷怪和计时，不继续下一关。原有村民升级功能保持原样；这里不额外添加任何自动治疗。

## 场景对象和脚本

`GameSystems` 已挂载：

- `GameFlowTimer`：配置解析、三关状态、传送、倒计时、开始入口 `StartGame()`。
- `MonsterSpawner`：预制体绑定、间隔刷怪、死亡统计、怪物与敌方箭矢清理。
- `GameFlowHud`：跟随玩家相机的世界空间阶段/时间/存活数量显示。

`GameSystems/TeleportPoints` 包含 `WaitingPoint`、`PreparationPoint`、`CombatPoint`。在编辑器移动和旋转这些空物体可以调整传送位置和角色根物体朝向。

`GameSystems/MonsterSpawnPoints` 包含六个出生点。刷怪时采样怪物对应的 NavMesh，且要求能走到战斗区玩家位置；没有有效出生点时会明确报错并停止流程。

现有三个 `ItemSpawner` 由 `GameFlowTimer` 引用，资源额度由 JSON 覆盖 Inspector 里的旧 `maxCount`。`MonsterHealth` 在血量归零时发出死亡事件，避免等尸体消失后才结束回合。

`Tools > CraftFight > Set up three-round game` 可重新绑定当前 MainScene，会把传送点和出生点恢复到本次默认位置并保存场景；手动调点后无需再次运行这个菜单。

## 验证

`Tools > CraftFight > Validate three-round game` 运行自动 Play Mode 检查，结果写入 `Docs/ThreeRoundGameValidation.txt`。验证仅在内存中提前结束计时，不修改 JSON 的正式数值。验证包括分批生成、清怪提前结束、超时返回、资源额度、血量/装备保留、三关结束和玩家死亡。

自动流程检查与 Game View 截图不等于头显/手柄实机验证。
